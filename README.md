# AI는 왜 이 질문을 거절했을까?

> AI 안전 필터는 유해한 질문과 프롬프트 공격을 어떻게 구별할까?

## 1. 프로젝트 소개

생성형 AI는 모든 질문에 답하지 않는다. 어떤 질문에는 답변하고, 어떤 질문에는 거절하거나 입력을 차단한다.

그렇다면 AI 서비스는 어떤 기준으로 질문을 판단할까? 단순히 특정 단어를 포함하는지 확인하는 것일까, 아니면 질문의 내용과 공격 패턴을 구분하는 별도의 기술이 존재할까?

이번 발표에서는 Microsoft Azure의 **Azure AI Content Safety**와 **Prompt Shields**를 중심으로 AI 안전 필터의 역할과 차이를 살펴보고, Python 기반 데모와 실험을 통해 직접 확인한다.

## 2. 핵심 질문

- 무엇을 '나쁜 질문'이라고 정의할 수 있을까?
- 유해한 콘텐츠와 프롬프트 인젝션은 어떻게 다를까?
- 표현이나 맥락이 달라지면 탐지 결과도 달라질까?
- 탐지 결과를 실제 서비스의 허용·경고·차단 정책으로 어떻게 연결할 수 있을까?

## 3. 기술 스택

- Python
- Azure AI Content Safety
- Azure AI Content Safety의 Prompt Shields 기능
- Streamlit (데모 웹 UI)

## 4. 주요 기술

### Azure AI Content Safety

텍스트에 포함된 유해 콘텐츠를 탐지하는 기능이다. 지원되는 범주와 심각도 수준 등의 결과를 확인하고, 서비스가 어떤 입력을 허용할지 판단하는 데 활용할 수 있다.

### Prompt Shields

사용자 입력이나 외부 콘텐츠에 포함된 프롬프트 인젝션 및 지시 조작 시도를 탐지하는 기능이다. 일반적인 유해 콘텐츠 탐지와는 목적이 다르다.

이번 발표에서는 두 기능의 입력과 출력, 탐지 목적을 비교하고 각각의 결과를 실제 서비스 정책에 어떻게 활용할 수 있는지 살펴본다.

## 5. 실험 및 데모

### 실험 1. 같은 주제, 다른 맥락

- 유해 물질 사고를 예방하는 방법을 묻는 질문
- 유해 물질로 다른 사람을 해치는 방법을 묻는 질문

### 실험 2. 다른 표현, 비슷한 의도

- 타인의 계정에 무단으로 접근하는 방법을 직접적으로 묻는 질문
- 같은 의도를 다른 표현으로 감춘 질문

### 실험 3. 오탐과 미탐 가능성

- 범죄 예방·분석처럼 유해한 단어가 포함되어도 정당한 목적이 있는 입력
- 위험한 의도를 간접적으로 표현한 입력

### 실험 4. 프롬프트 인젝션

- 기존 지시를 무시하고 숨겨진 지침을 공개하라고 요구하는 입력

각 실험에서 실제 API 결과를 기록하고, 예상과 다른 결과가 나타났다면 그 원인을 분석한다. 결과를 미리 단정하지 않고 실제 관측값을 기준으로 비교한다.

## 6. 데모 흐름

1. 사용자가 문장을 입력한다.
2. Content Safety와 Prompt Shields의 목적에 맞춰 입력을 검사한다.
3. 각 기능의 실제 탐지 결과를 확인한다.
4. 개발자가 정한 정책에 따라 허용·경고·차단 결과를 표시한다.
5. 여러 실험 결과를 비교하고 한계점을 분석한다.

※ 두 기능은 서로 다른 목적을 가지므로 모든 입력에 두 검사를 무조건 동일하게 적용하기보다, 서비스의 사용 목적에 맞춰 검사 대상을 설계한다.
